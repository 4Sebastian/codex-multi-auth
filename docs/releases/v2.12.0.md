# v2.12.0

Cost tracking is more accurate now: models with `max` or `ultra` effort suffixes stay one model, and usage is priced at the tier you were actually billed at. Nothing to migrate.

## Fixes
- Effort suffixes `max` and `ultra` (added with GPT-5.6) are now stripped like the others, so `gpt-5.6-sol-max` and `gpt-6-astra-ultra` share caches, stats and fallbacks with their base model.
- `--model gpt-6-astra-max` now gets the same fallback as `gpt-6-astra`.
- Chain overrides in your config that use those suffixes now actually apply.
- `codex-max` and `gpt-5.1-codex-max` are real model names and are left alone.
- Usage is now priced by the service tier upstream reports. Before, a Fast session was recorded at half its real cost ($20/$100 vs $10/$50 for GPT-6 Astra), so a `maxCostUsd` cap could overrun.
- A tier with no published rate now shows unknown cost, and the budget guard fails closed, same as an unpriced model. That includes `priority` on `gpt-5.6-sol`.
- `gpt-6-astra` cached tokens are now billed at $1 standard and $2 on Fast (the usual 90% discount) instead of the full input rate, which tripped cost caps far too early.
- Fast responses through the runtime proxy now keep their tier all the way to the ledger, and Fast rows no longer read back as standard in `usage` reports.

## Heads up
- Nothing in this package picks a service tier. `fastSession` is a local latency setting that lowers reasoning effort, not OpenAI's billed Fast mode.
- If your responses carry no `service_tier`, pricing is exactly the same as 2.11.0.
- Model routing is unchanged: `DEFAULT_MODEL` stays `gpt-5.5` and diagnostic probes still lead with `gpt-5.6-sol`.
- Existing ledger rows are unaffected. A row with no recorded tier prices as standard, same as before.

## Upgrade

```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

It should report `2.12.0`.
