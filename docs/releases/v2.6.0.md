# v2.6.0

A follow-up to the GPT-5.6 launch in v2.5.0: diagnostics probe with GPT-5.6, model pickers show the new tiers, and parallel agents spread across accounts by default.

## What's new
- `check`, `report`, `forecast`, `best` and `fix` now probe with `gpt-5.6-sol`, falling back to `gpt-5.5`, then `gpt-5.4`, then codex for accounts without 5.6 access. `check` shows `Model probe: gpt-5.6-sol`.
- The probe uses the cheapest reasoning effort each model supports, instead of always sending `reasoning.effort: "none"`.
- `pidOffsetEnabled` now defaults on, so parallel agents spread across accounts instead of all picking the same one and hitting `429`s.
- New "high parallelism / swarms of agents" playbook in the troubleshooting and configuration docs.

## Fixes
- GPT-5.6 tiers now show up in older Codex builds. The legacy config template was missing them.
- Upgrading your config no longer skips new models. New template models get added and your own customisations are kept.
- The `codex-multi-auth-codex` wrapper now understands GPT-5.6. Before, a `gpt-5.6-*` request through it mangled the reasoning effort and silently became `gpt-5.5`.
- Docs now match the code: `retryAllAccountsRateLimited` defaults to `false` and `retryAllAccountsMaxRetries` to `0`.
- Docs clarify that `Provider response headers timed out after 10000ms` comes from the host client's own timeout, not from us.

## Heads up
- Only the probe moved to 5.6. `DEFAULT_MODEL` and the `gpt-5` alias stay on `gpt-5.5`. Routing, rotation, storage and auth are unchanged.
- On an existing install, re-run the config install and restart the app or extension to see the 5.6 tiers in a picker.
- `pidOffsetEnabled` does nothing for single-account pools, and pins and health scoring still win. Turn it off with `pidOffsetEnabled: false` or `CODEX_AUTH_PID_OFFSET_ENABLED=0`.

## Upgrade
```bash
npm i -g codex-multi-auth
```
