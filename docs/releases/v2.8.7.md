# v2.8.7

Two fixes for how the wrapper reads your command line, and a clearer error when a pinned account is unavailable. Nothing to migrate.

## Fixes
- `codex "your prompt"` no longer takes the slow startup path. It now keeps your real `CODEX_HOME` and thread index, same as bare `codex`, so no rebuild and no stall.
- A prompt forced with `--` counts as a prompt, so `codex -- exec` opens a session whose prompt is the word "exec", matching how Codex parses it.
- Everything after `--` stays prompt text. `--account`, `-m` and `--config=` inside a prompt are no longer stripped, read as settings, or rewritten.
- Before, `codex -- --account 3 is wrong, fix it` pinned the run to account 3 (or failed with `--account 3 is out of range`), and `codex -- -m gpt-4 please fix this` was treated as a request for `gpt-4`.
- The wrapper's own `-c cli_auth_credentials_store="file"` now goes before `--` instead of at the end. This fixes `codex exec -- ...` failing with `unexpected argument '-c' found`, `codex sandbox -- echo hi` passing it to the command, and `codex mcp add t -- echo hi` writing it into that server's `args` in `config.toml`, where it stayed.
- The pinned-account 503 (`codex_pinned_account_unavailable`) now says what is actually holding the account, instead of always blaming your quota or showing `already-attempted`.

The new 503 messages:

| What is holding the account | What the message says |
| --- | --- |
| A rate limit, and the limit is what bounds recovery | `(rate-limited); the rate limit resets at ...` |
| A rate limit, but a cooldown or breaker ends later | `(rate-limited); the account is expected to be available again at ...` |
| An open circuit breaker | `(paused after repeated upstream errors); the next attempt is allowed at ...` |
| A cooldown | `(cooling down after upstream server errors); the cooldown ends at ...` |

## Heads up
- Only the human-readable `message` changed. The `reason` field still reports the selection verdict verbatim, and `reset_at` and `retry_after_ms` are untouched.

## Upgrade
```bash
npm i -g codex-multi-auth
```
