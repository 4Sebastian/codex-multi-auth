# v2.7.0

`check` now shows *when* your quota comes back, not just how much is left. Nothing to migrate.

## What's new
- `check` adds a reset time to each quota window ([#633](https://github.com/ndycode/codex-multi-auth/issues/633)):

```console
✓ Account 1 (...) | live session OK (5h 100%, resets 18:10 | 7d 93%, resets 13:50 on Jul 29)
```

- Times are local, 24-hour. A reset later today shows as `HH:MM`, and one past midnight adds the date.
- Only `check` shows this. The dashboard, account menu and `forecast` look exactly like v2.6.1.
- If reset data is missing or broken, the reset part is just left out. The percentage still shows.
- Window labels come from the backend, falling back to `quota` when missing.
- The docs were rewritten to match the current CLI and config ([#632](https://github.com/ndycode/codex-multi-auth/pull/632)).
- New `check` reference section. Unlike `fix`, `check` doesn't skip disabled accounts: it checks every stored account and re-enables any whose token still works.

## Fixes
- Quota percentages keep their red/yellow/green colours. Adding the reset text would otherwise have greyed them all out.

## Heads up
- The date part follows your system locale: `Jul 29` under en-US, `29 Jul` under en-GB, `7月29日` under ja-JP. The `HH:MM` part is stable. Don't parse the date.
- Routing, rotation, storage and quota math are unchanged.

## Upgrade
```bash
npm i -g codex-multi-auth
```
