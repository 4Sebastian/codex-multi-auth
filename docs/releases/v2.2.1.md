# v2.2.1

`mcodex` works on Windows again, plus a batch of fixes for race conditions and bad input.

## What's new
- `gpt-5.5` is now the default probe model, with the older ones kept as fallback.
- Accounts that can't use Codex now show as "signed in", not "working". Live check counts `Codex available`, `signed in only` and `need re-login` separately.
- Policy-blocked and token-exhausted accounts are left out of recommendations.

## Fixes
- `mcodex` crashed on Windows with `HCS_E_SERVICE_NOT_AVAILABLE` when a WSL stub shadowed git-bash. It's now a Node script and doesn't need bash by default.
- `mcodex` no longer breaks when `tmux` or `watch` aren't installed.
- `mcodex` now follows npm-created symlinks and passes `SIGTERM`/`SIGINT` on to the child, so it never gets orphaned.
- Two logins at the same time could mix up each other's callback code and state. Each login now keeps its own.
- The local token store no longer trips over overlapping writes, and retries more on temporary Windows file locks.
- Fixed a race in account selection when `routingMutex="enabled"`.
- A request with no model was billed to the general `gpt-5.5` bucket instead of the codex one, which threw off rotation, cooldowns and budgets.
- Incoming `cookie` and `proxy-authorization` headers are now stripped before forwarding.
- Auth is checked first, so you get a `401` instead of a `404`.
- Fixed a deadlock where recovering flagged storage could freeze every save after it.
- A `doctor` restore no longer wipes your manual pin.
- Secret folders are created as `0o700`. Fractional indices are rounded down and `NaN` no longer spreads.
- A failed live check that shows a quota percentage is now red, not green.
- `--model` no longer swallows the next flag. Flag-like or blank values after it are rejected.
- Non-integer `workspace` and `switch` indices are rejected instead of quietly truncated.

## Upgrade
```bash
npm i -g codex-multi-auth
```
