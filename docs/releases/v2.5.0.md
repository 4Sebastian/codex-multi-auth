# v2.5.0

Adds the GPT-5.6 family (Sol, Terra and Luna) plus two reasoning tiers above `xhigh`. It's opt-in: `gpt-5` still resolves to `gpt-5.5`, and defaults are unchanged.

## What's new

| Model | Default effort | Notes |
| --- | --- | --- |
| `gpt-5.6-sol` | `low` | Bare `gpt-5.6` resolves here |
| `gpt-5.6-terra` | `medium` | |
| `gpt-5.6-luna` | `medium` | No `ultra` tier |

- Sol's low default is on purpose. It matches upstream.
- New tiers above `xhigh`: `max` on all three models, `ultra` on Sol and Terra only.
- `ultra` is selectable in config and model ids but is sent as `max`, same as upstream Codex does.
- 5.6 models don't accept `none` or `minimal`. Those get bumped up to a supported effort instead of failing.
- Pricing per 1M tokens: Sol `$5` in / `$30` out, Terra `$2.50` / `$15`, Luna `$1` / `$6`. Cached input is 10% of input.

## Fixes
- `gpt-5.1-codex-max` keeps routing to Codex Max instead of being treated as `gpt-5.1-codex` at max effort.
- Unrecognised `gpt-5.6-*` ids no longer silently run GPT-5.5.

## Heads up
- No fallback: an account without GPT-5.6 access fails the request instead of quietly dropping to 5.5.
- Model facts come from the upstream Codex catalog and client source, not the API docs, which disagree on `max` and advertise a context window for the API rather than the ChatGPT Codex backend.
- 5.6 uses the `gpt-5.2` prompt family, since upstream ships no 5.6 prompt file.

## Upgrade
```bash
npm i -g codex-multi-auth
```
