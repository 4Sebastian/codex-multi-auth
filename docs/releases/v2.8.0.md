# v2.8.0

macOS stops asking for your keychain password over and over, and interactive sessions stop reindexing your history on every launch. Nothing to do when you upgrade.

## Fixes
- Apps like CodexBar that run the official `codex` binary kept triggering keychain prompts, and "Always Allow" never stuck. The official CLI reads `cli_auth_credentials_store` from `~/.codex/config.toml` and uses the keychain when it says `"keychain"`.
- The wrapper now sets it to `"file"` on first run and checks it again on startup. That also fixes a config something else flipped back, like a fresh official `codex login`.
- `doctor --fix` can repair this too, even on a machine with no accounts added yet.
- Interactive sessions now run in your real Codex home instead of a temp copy. No more reindexing on launch and no syncing back on exit.
- Interactive sessions never rewrite your `config.toml` with a rotation provider.
- You can run two sessions at once against the same state, just like running the official CLI twice.

## Heads up
- This is a minor release because behaviour changed: `cli_auth_credentials_store` is now written into `~/.codex/config.toml` on first run and on startup, not only during login, switch or repair.
- Only the top-level setting changes. Anything in `[profiles.*]` tables stays as you wrote it, line endings are kept, and `'file'` in single quotes already counts as correct.
- Nothing reads or deletes your keychain items. Old credentials just stop being read. You can remove them by hand in Keychain Access.
- Non-interactive commands, `codex app` and `app-server` are unchanged.
- If you were already installed, only the new credential-store step runs again. App bind and launcher install don't rerun, so shortcuts you removed stay removed.
- Opt-outs are in [docs/configuration.md](../configuration.md).
- `CODEX_MULTI_AUTH_ENFORCE_CLI_FILE_AUTH_STORE=0` never writes `cli_auth_credentials_store` into `config.toml`. Set this one to keep keychain behaviour for apps like CodexBar.
- `CODEX_MULTI_AUTH_FORCE_FILE_AUTH_STORE=0` also stops passing it to sessions the wrapper launches. Set both if you want the keychain everywhere.

## Upgrade
```bash
npm i -g codex-multi-auth
```
