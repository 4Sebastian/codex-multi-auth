# v2.11.0

Asking for GPT-6 Astra or the Daybreak cyber models now actually runs them instead of quietly running GPT-5.5. Five bugs found along the way are fixed too. Nothing to migrate.

## What's new
- GPT-6 Astra support: `gpt-6-astra` (the flagship) and `gpt-6-astra-aeon` (a long-horizon variant for runs measured in days). OpenAI shipped both on 2026-09-03.
- `gpt-6`, `gpt6`, `astra` and `astra-aeon` work as aliases.
- Both Astra models take effort `low` through `max` plus `ultra`. `none` and `minimal` get bumped up to `low`, and `ultra` is sent as `max`, same as upstream Codex.
- Here's how GPT-6 ids resolve:

| You ask for | You get |
| --- | --- |
| `gpt-6-astra`, `gpt-6`, `astra` | `gpt-6-astra` |
| `gpt-6-astra-aeon`, `astra-aeon` | `gpt-6-astra-aeon` |
| `gpt-6-astra-pro`, `gpt-6-astra-2026-09-03`, `Astra Pro` | `gpt-6-astra` |
| `gpt-4-astra-x` | not GPT-6, the `astra` branch is anchored to a GPT-6 version token |
| `gpt-6-codex` | left to the codex resolver, unchanged |

- Daybreak support: `gpt-daybreak-blue-latest` and `gpt-daybreak-red-latest`, with `daybreak-blue` and `daybreak-red` as shorthands.
- An unknown Daybreak id goes to `blue`, the defensive one, so a typo can't land you on the cyber-permissive model. Daybreak stays out of the picker templates, matching upstream.
- `gpt-6-astra` is priced at `$10` per 1M input and `$50` per 1M output (standard tier). Cached input bills at the full input rate since no cached rate was published.
- If an account isn't entitled to Astra yet, it steps down instead of failing: `gpt-6-astra-aeon` to `gpt-6-astra`, `gpt-6-astra` to `gpt-5.6-sol`, `gpt-5.6-sol` to `gpt-5.5`.

## Fixes
- A GPT-6 id used to fall through to `DEFAULT_MODEL` and silently run GPT-5.5, billed and rate-limited as a different family.
- The Daybreak models also silently ran GPT-5.5.
- Model names like `constructor`, `__proto__` and `toString` were treated as real model ids. They no longer match anything.
- A bad model name could make a `maxCostUsd` cap impossible to enforce. It now fails closed.
- Fixed a `TypeError: targets is not iterable` crash in the request path.
- `models --model constructor` no longer prints a row of undefined fields.
- The `codex-multi-auth-codex` wrapper didn't resolve ids like `gpt-6-codex` while the library did. They now match.
- Model ids with a provider prefix, like `openai/gpt-6`, `openai/gpt-5.6-sol` or `openai/gpt-5.1`, now route status to the right family instead of `activeIndex`.

## Heads up
- `gpt-6-astra-aeon` and both Daybreak models have no published price. They're listed in `UNPRICED_ROUTABLE_MODELS`, so a cost budget blocks them instead of counting them as free.
- OpenAI's Fast service tier costs 2x standard, but pricing doesn't track tier, so Fast sessions under-count Astra cost by half (same as `gpt-5.6-sol` already). Nothing here selects that tier.
- All four new models are in `UNESTIMATED_ROUTABLE_MODELS`. OpenAI published two context windows (1.05M for the API, 272K for Codex), and this wrapper talks to Codex. Set `contextBudgetGuardModelWindowOverrides` once you know your real limit.
- In the plugin-host runtime, the Astra step-down only happens when `fallbackOnUnsupportedCodexModel` is on, and it defaults to `false`.
- The `codex-multi-auth-codex` wrapper has always retried on an unsupported-model response, and prints the swap to stderr.
- Each step-down uses one of the request's shared outbound attempts. A single-account balanced session gets 5, and the longest Astra chain uses all 5. If one also goes to a retry or stream failover, you get an attempt-budget-exhausted 503. This only hits an account entitled to none of aeon, Astra, Sol or 5.5.
- Defaults are unchanged. `DEFAULT_MODEL` stays `gpt-5.5` and diagnostic probes still lead with `gpt-5.6-sol`. You only get Astra by asking for it.

## Upgrade

```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

The command should report `2.11.0`.
