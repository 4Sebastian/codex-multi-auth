# v2.3.0-beta.0

Beta: adds an opt-in "drain-first" mode that uses up one account before moving to the next.

## What's new
- New `sequential` scheduling mode ([#509](https://github.com/ndycode/codex-multi-auth/issues/509)). Turn it on with:

```bash
CODEX_AUTH_SCHEDULING_STRATEGY=sequential
```

- Requests stay on the current account until it is rate-limited, cooling down, circuit-open or disabled, then move to the next usable one.
- When an earlier account's quota window recovers, it takes the slot back on the next scan.
- The idea: your quota windows reset at staggered times instead of all together, which should mean longer uninterrupted sessions.

## Heads up
- `hybrid` is still the default and works exactly as before. If you don't set this, nothing changes.
- A manual `switch <n>` pin still overrides scheduling in both modes.
- In `sequential` mode, per-session affinity is off. Every request follows the one active account, not a per-chat sticky one.
- It's a beta because whether it really gives longer sessions depends on your pool's real quota timing. It needs testing on real accounts before a stable release.

## Upgrade
```bash
npm i -g codex-multi-auth@beta
```
