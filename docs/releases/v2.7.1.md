# v2.7.1

A bug-fix release with no new features and no config changes. Worth upgrading if you run more than one account.

## Fixes
- A manual pin could quietly route to a different account after another account was removed. Pins now follow the account itself and clear if it's gone.
- One failed token refresh no longer blocks refreshes for every process for 20 seconds. Only successful refreshes are shared now, so a cached `429` can't bench a healthy account.
- A refresh waiting on the shared lease could start a second refresh at 30 seconds and fail with `invalid_grant` on a healthy account. Fixed.
- Monthly (Codex Business) quota windows were labelled `5h`. Labels now match the real window length. The numbers were always right.
- An account at 100% used with no reset time is no longer marked `ready` or recommended.
- An account at `99.6%` used no longer rounds to `0%` left and gets benched while it still has quota.
- `import` and legacy migration no longer drop your pin or reset the affinity counter, which could let a running proxy overwrite a newer pin.
- Session trimming no longer cuts off the leading instructions it meant to keep.
- A truly empty completion (`output: []`) now triggers the empty-response retry.
- Timed-out requests now get their rate-limit token back, which stops spurious `token-exhausted` skips over time.
- Project- and profile-scoped budgets with uppercase or spaces in the key (like a project named `MyApp`) now actually apply.

## Heads up
- Monthly-quota accounts now show `30d` where they showed `5h`. The numbers are the same.
- Project- and profile-scoped budgets that did nothing before will now enforce. If you set one earlier and saw no effect, check it before upgrading.

## Upgrade

```bash
npm i -g codex-multi-auth
```
