# v2.17.1

Prepared but never published — npm, the git tag, and the GitHub release all went straight to [v2.17.2](v2.17.2.md), which carries every fix listed below. These notes are kept as the record of what 2.17.1 contained.

Automatic subscription priming now observes each selected workspace on its own record, keeps shared-organization accounts separate, and merges concurrent quota observations instead of overwriting them. Also fixes app-bind cleanup on non-English POSIX systems, where every process identity probe failed and unbind leaked the routers and helpers it owned.

Landed as [#706](https://github.com/ndycode/codex-multi-auth/pull/706) plus a locale fix on main.

## Fixes

- Automatic first-use checks now prime each saved account's selected workspace independently: quota observations are keyed by the credential record and the exact workspace, so members of a shared organization no longer collide on a single organization id, and a Personal-workspace check no longer deletes the organization binding's valid entry ([#706](https://github.com/ndycode/codex-multi-auth/pull/706)).
- Quota cache writes now merge under the cross-process file lock against a pre-edit baseline, so a background save from an older session can no longer discard a workspace observation another process just wrote ([#706](https://github.com/ndycode/codex-multi-auth/pull/706)).
- Pending rotated credentials now carry `recordId`, so an account whose token refresh persisted through the pending-auth journal keeps its identity key and is not probed twice ([#706](https://github.com/ndycode/codex-multi-auth/pull/706)).
- `unbind-app` and helper cleanup now verify process start times on non-English POSIX systems: the `ps -o lstart=` probe pins `LC_ALL=C`, matching `scripts/codex.js`. Previously the probe could never parse the localized output, every identity check failed, and unbind left live router/helper processes behind ([`fc37c3ec`](https://github.com/ndycode/codex-multi-auth/commit/fc37c3ec)).
