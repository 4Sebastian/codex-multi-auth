# v2.3.2

You can now fix a stuck app-bind setup from the CLI, even without a saved backup.

## Fixes
- If app-bind's state and backup files went missing, `~/.codex/config.toml` stayed pointed at a dead rotation proxy while `rotation status` and `rotation unbind-app` said "not configured". The official Codex CLI and Desktop were stuck ([#614](https://github.com/ndycode/codex-multi-auth/pull/614)).
- `rotation unbind-app` now repairs this itself. It removes the proxy block, restores your `model_provider` (or `openai` if there's no backup), and tells you what it did.
- `rotation status` now says "bound but unmanaged" and shows the fix to run.
- Restoring a half-broken config no longer adds a second `model_provider` line that Codex can't parse.

## Heads up
- If you hit this, run:

```bash
codex-multi-auth rotation unbind-app
```

## Upgrade
```bash
npm i -g codex-multi-auth
```
