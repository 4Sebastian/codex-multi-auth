# v2.9.0

Cost and token budgets finally work, network drops stop hurting your accounts, and three quieter bugs are fixed. Nothing to migrate.

## Fixes
- `budget set --cost` and `--tokens` were saved and shown but never enforced. Usage was always recorded as zero tokens and $0.00, so only `--requests` did anything. Both caps now work.
- `codex-multi-auth usage` now shows real token and cost numbers instead of `0` and `$0.00`.
- Reasoning tokens are no longer billed twice, so a cost cap won't trip early on reasoning-heavy requests.
- A streaming request is recorded when the stream finishes. If your client disconnects mid-stream, the request is still recorded, just without token counts.
- A connection that dies before any response (socket reset, TLS drop, 60-second timeout) no longer counts against the account's health. Before, a network blip could trip the circuit breaker on every account in your pool.
- The account still gets its short `network-error` cooldown and the request still moves to the next account. These failures now also log an error line.
- Deleting an account, restoring a backup, or auto-removing an account with a revoked token no longer sends running conversations to the wrong account.
- `account pause`, `account drain` and tags no longer hit every account that has no `accountId` or email yet. Before, pausing one paused them all.
- A slow client no longer makes the whole streamed response pile up in memory.

## Heads up
- Cost caps only know the prices in `MODEL_PRICING`, which covers nine model ids.
- Models like `gpt-5.1-codex-max`, `gpt-5.2-codex`, `gpt-5.3-codex-spark` and the `pro`/`mini`/`nano` variants record tokens correctly but price at zero, so `maxCostUsd` under-counts them.
- `maxTokens` covers every model. If you rely on a cost cap, use a token cap until the price table is filled in.

## Upgrade

npm i -g codex-multi-auth
