# v2.9.0

Cost and token budgets are enforced for the first time, a broken network path stops counting against your accounts, and three quieter defects around account removal, account policy, and streaming are fixed. Nothing to migrate — install and go.

```bash
npm i -g codex-multi-auth
```

## What was wrong

**`budget set --cost` and `--tokens` never did anything.**

Both limits were accepted, stored, and displayed, and neither was ever enforced. Nothing read the `usage` object off the upstream response, so every row the usage ledger wrote recorded zero input tokens, zero output tokens, and a zero cost. The guard that checks a budget compares consumption against the limit — and consumption was always `0`, so `0 >= 50` was never true and the request always passed.

The visible symptom was `codex-multi-auth usage`:

```
MODEL           REQUESTS   TOKENS   COST
gpt-5.1-codex        412        0  $0.00
```

412 requests, no tokens, no spend. A `--cost 50` cap on that account had allowed every one of them. Only `--requests` was actually enforcing anything.

**A dead network path counted against your accounts.**

When the connection to the upstream failed before any response headers arrived — a socket reset, a TLS drop, a connection that hung until the 60-second fetch timeout — the proxy recorded a failure against whichever account the request happened to be using. Those failures feed that account's circuit breaker, and three of them open it for roughly 30 seconds.

The account did nothing wrong. During a real connectivity problem every account collects those failures in turn, so a transient network fault could leave your entire pool sitting behind open circuit breakers while every credential in it was perfectly healthy.

**Removing an account silently rerouted live conversations.**

Session affinity keeps a conversation on one account by remembering that account's *position* in your list. A generation counter invalidates those bindings when the list changes, and only `switch`, `best`, and `unpin` bumped it.

Three things that reshuffle every position did not: deleting an account from the login menu, restoring a backup (which replaces the whole list), and the runtime account check auto-removing an account whose token was revoked. That last one needs no confirmation from you. After any of them, a running proxy kept routing in-flight conversations to whatever account had slid into the vacated slot.

**Two accounts with no identity yet shared one policy.**

`account pause`, `account drain`, and tags are keyed by account identity. An account with neither a resolved `accountId` nor an email — freshly imported, or not yet hydrated from its token — hashed the literal string `"unknown"`. Every such account therefore landed on the same key, so pausing one paused all of them.

**A slow client buffered the whole response in memory.**

The streaming-failover wrapper pulled from the upstream as fast as it arrived, without checking whether the client was keeping up. Measured directly: a 50-chunk response, a consumer that read exactly one chunk, and all 50 chunks pulled and held in memory.

## What's fixed

**Budgets count real usage.** The proxy and the plugin host both read the upstream `usage` object now — scanned out of the SSE stream as it passes through, so nothing is buffered — and write it to the ledger. `usage` reports real numbers, and `maxTokens` and `maxCostUsd` enforce.

| Recorded per request | Source |
| --- | --- |
| `inputTokens` | `usage.input_tokens` |
| `cachedInputTokens` | `usage.input_tokens_details.cached_tokens` |
| `outputTokens` | `usage.output_tokens`, less the reasoning share |
| `reasoningTokens` | `usage.output_tokens_details.reasoning_tokens` |
| `costUsd` | priced from the above, per model |

Reasoning tokens are reported by the upstream *inside* `output_tokens`, while the cost estimator prices the two separately — so the reasoning share is subtracted out before recording. Without that, every reasoning-heavy request would be billed for its reasoning twice and a cost cap would trip early.

A streaming request's ledger row is written when the stream finishes rather than when the request is handed off, since that is when the token counts exist. A request whose client disconnects mid-stream still records, without counts.

**Transport failures no longer damage account health.** A connection that dies before response headers is treated as a property of the network, not of the account: it no longer feeds that account's circuit breaker or health tracker. Everything else is unchanged — the account still takes its short `network-error` cooldown, the request still rotates to the next account, and a single transient reset is still invisible to you. Transport failures also now emit a trace-correlated error line, which they previously did not.

**Account removal invalidates session affinity.** Deleting an account, restoring a backup, and the automatic removal of revoked-token accounts all bump the generation counter, so a running proxy drops its stale bindings instead of routing conversations to the wrong account.

**Identity-less accounts get their own policy.** The key falls back to the account's refresh token instead of a shared literal, so pausing, draining, or tagging one no longer affects another. The key still does not depend on account position, so reordering your accounts leaves policy intact.

**Streaming respects a slow client.** The failover wrapper stops pulling from the upstream while the client's buffer is full and resumes when it drains, matching what the non-failover path already did.

## Known limitation

Cost enforcement is only as complete as the price table. `MODEL_PRICING` currently covers nine model ids, and several models this package routes — including `gpt-5.1-codex-max`, `gpt-5.2-codex`, `gpt-5.3-codex-spark`, and the `pro`/`mini`/`nano` variants — are not among them. Requests to those models record their token counts correctly but price at zero, so `maxCostUsd` under-counts them. `maxTokens` is unaffected and covers every model. If you rely on a cost cap, prefer a token cap until the table is filled in.
