# v2.8.1

`mcodex resume` no longer hangs on a blank screen, your shell prompt comes back reliably, and four security advisories are patched.

## Fixes
- `mcodex resume <session-id>` sat on a blank screen because `resume` and `fork` ran on a temporary copy of your Codex home with no session database. They now use your real Codex home, and rotation still applies ([#647](https://github.com/ndycode/codex-multi-auth/issues/647)).
- After an interrupted or failed Codex exit, the shell prompt could hang. Shutdown now force-kills after the grace window and frees things properly on Windows.
- `--help` (like `resume --help`) no longer starts a rotation proxy or leaves a helper running. It goes straight to the official CLI.

## Heads up
- Security: `hono` 4.12.21 -> 4.12.33 fixes JSX context leaking between requests and an XSS via the `cx()` escaping bypass.
- Security: `undici` 6.25.0 -> 6.28.0 fixes Set-Cookie injection, a WebSocket fragment DoS, keep-alive queue poisoning and a SameSite downgrade.
- `undici` stays on 6.x on purpose, since 7.x would need Node 20 and the floor is Node 18.17. Two dev-only advisories are pinned through `overrides`.
- If you set `CODEX_MULTI_AUTH_RUNTIME_ROTATION_PROXY=0` to work around the resume hang, remove it. It worked by turning rotation off.

## Upgrade

```bash
npm i -g codex-multi-auth
```

To check it worked, this should open the session, and `/exit` should give your prompt back:

```bash
mcodex resume <session-id>
```

To drop the workaround:

```bash
unset CODEX_MULTI_AUTH_RUNTIME_ROTATION_PROXY
codex-multi-auth rotation status
```
