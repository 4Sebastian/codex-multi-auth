# v2.8.5

Fixes background rotation helpers that never shut down and piled up. Nothing to migrate.

## What's new

- `CODEX_MULTI_AUTH_APP_ROTATION_MAX_LIFETIME_MS` (default 24h) caps how long a helper can live. `0` turns it off.
- `CODEX_MULTI_AUTH_APP_ROTATION_DETACHED_IDLE_MS` (default 15m) is a shorter timeout for a helper whose launcher died and that never served a request. `0` keeps the old 12h behaviour.
- That second one is narrow on purpose: an idle `codex app` session holds no connection, so anything broader would kill working sessions.
- Removed the deprecated `@openauthjs/openauth` dependency. PKCE now comes straight from `node:crypto` (RFC 7636).
- Test-only failure hooks in the published wrapper now need an explicit opt-in, so a stray env var can't turn one on.

## Fixes

- Background helpers never exited. One user had 183 of them using 5.58 GB, and their machine was swapping.
- Helpers now recognise their launcher by process ID and start time, so a reused process ID no longer keeps them alive.
- A hard 24-hour limit now stops any helper, no matter what its activity tracking says.
- Each helper writes its own status file, and leftover files get cleaned up on the next launch (one machine had 701).
- `rotation status` now gives one consistent answer instead of mixing up two different helpers.

## Heads up

Already affected? Count your helpers, then clean up:

```bash
ps ax | grep -c 'codex-multi-auth-runtime-app-helper'
codex-multi-auth rotation unbind-app
```

- `unbind-app` stops every helper it can confirm is yours and clears their files. Anything it can't verify is left alone with a warning.
- If you read `~/.codex/multi-auth/runtime-rotation-app-helper.json` directly, switch to `runtime-rotation-app-helper.<pid>.json`. The old path is still read, but nothing writes it anymore.

## Upgrade

```bash
npm i -g codex-multi-auth
```
