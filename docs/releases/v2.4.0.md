# v2.4.0

You can now force a single run onto one account with `--account`. If you don't use it, nothing changes.

## What's new
- `--account` takes a 1-based index (as in `codex-multi-auth list`), an email or an account id. All-digit values are always read as an index. ([#623](https://github.com/ndycode/codex-multi-auth/issues/623), [#624](https://github.com/ndycode/codex-multi-auth/pull/624))
- `CODEX_MULTI_AUTH_FORCE_ACCOUNT=<selector>` does the same thing. If you set both, the flag wins.
- It only applies to that one run and never touches your saved `switch` pin, so parallel runs with different accounts don't clash.

```bash
codex-multi-auth-codex --account 2 "your prompt"
codex-multi-auth-codex --account you@example.com "your prompt"
```

## Heads up
- A forced run never rotates. If that account is rate-limited or unavailable, the request fails instead of using another account.
- If the selector doesn't match an account, or rotation is disabled, the wrapper exits non-zero without starting Codex. This is on purpose: an error beats billing the wrong account.

## Upgrade
```bash
npm i -g codex-multi-auth
```
