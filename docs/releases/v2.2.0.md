# v2.2.0

Adds the `mcodex` launcher, which shows what you're about to run before Codex starts, plus a security pass over the proxy and storage.

## What's new
- `mcodex` shows model, reasoning effort, working directory, active account, quota usage, plan and cache age, then starts Codex.
- The status line reads only local state and never calls OpenAI on launch. Quota refreshes in the background when stale (10 minutes by default, `CODEX_MULTI_AUTH_STATUS_QUOTA_REFRESH_INTERVAL_MS`).
- Turn the status line off with `CODEX_MULTI_AUTH_STATUSLINE=0`.
- `--monitor` and `--live-accounts` fail fast if `watch` isn't installed.
- `status` and `list` now support `--json`, with the same shape whether or not you have accounts.
- Unsupported Codex models now show a readable "Codex unavailable" note in `best`, `forecast`, `report` and live checks. Real transient errors still show as themselves.

```bash
mcodex                          # status line, then Codex
mcodex --tmux                   # inside tmux with mouse scrollback
mcodex --tmux --live-accounts   # adds a live account pane
mcodex --monitor                # monitor only
```

## Fixes
- `switch <index>` now requires a real integer instead of silently truncating a float.

## Heads up
- The rotation proxy and local bridge now bind to loopback only, with no opt-out.
- They no longer forward your inbound `authorization`, `x-api-key`, `cookie` or `proxy-authorization` headers upstream.
- Cached Codex instructions are SHA-256 verified, so a tampered cache is never used.
- Stored ids are checked before being used in file paths. An id like `../poison` is quarantined.
- The account store now writes atomically, heals itself, and retries through transient Windows lock errors.
- Runtime observability files are owner-only on POSIX.
- Tokens and emails are masked in logs, the debug bundle and status output. The debug bundle also hides your home directory and strips config credentials.

## Upgrade

```bash
npm i -g codex-multi-auth
```
