# v2.13.0

Two new machine-readable surfaces, a manual `switch` that now actually
revalidates a rate-limited account, and hardening around the selection counter
the runtime proxy watches. No user configuration migration is required.

Landed as [#688](https://github.com/ndycode/codex-multi-auth/pull/688),
[#690](https://github.com/ndycode/codex-multi-auth/pull/690) and
[#691](https://github.com/ndycode/codex-multi-auth/pull/691).

## What was wrong

**`switch` did not clear the account's rate-limit windows.** After a quota reset
landed out of band, running `codex-multi-auth switch 2` set the pin and nothing
else. The account's `rateLimitResetTimes` entries survived, so the runtime proxy
still treated the account as blocked and kept deferring or returning 503 until
the recorded window expired on its own. The one command whose whole purpose is
"use this account now" could not unblock it.

**The proxy kept a stale quota reading across a switch.** The preemptive quota
scheduler caches the last quota observation per account and model. On a selection
change the proxy cleared session affinity and nothing else, so a pre-switch
reading kept driving preemptive deferrals against the account you had just
selected.

**A failed background save was dropped, not retried.** The debounced save clears
its timer before the save runs. When the write failed, for instance because a
Windows antivirus scanner or indexer held `accounts.json` open, it logged a
warning and gave up. Every rate-limit window, cooldown and rotated refresh token
recorded since the last successful write went with it.

**A failed flush aborted proxy shutdown.** `RuntimeRotationProxy.close` awaits
`flushPendingSave()` with no catch, so a save failure during teardown rejected
out of the close path.

**A corrupt selection counter could hide every future switch, permanently.**
`affinityGeneration` in `accounts.json` is how a running proxy notices that you
changed accounts: `switch`, `unpin` and `best` increment it and the proxy watches
it. Every validator accepted any integer, including one past 2^53, where
`Math.max(counter, disk) + 1` equals the counter itself. One hand edit or
corrupted write to a 16-digit value froze it: every later switch wrote the same
number, and no running proxy observed another selection change again.

## What's fixed

- `switch <n>` clears the selected account's rate-limit windows as part of the
  same atomic storage write that sets the pin. A 429 that raced the switch is
  still preserved; one recorded earlier is not.
- The runtime proxy drops the switched account's cached quota observations when
  it observes the new selection generation, so the next request probes upstream
  instead of deferring on a pre-switch reading.
- A failed debounced save re-arms with backoff and a bounded retry count instead
  of discarding the state.
- `flushPendingSave()` logs a failure at error level and resolves, so proxy
  shutdown completes.
- Every reader of `affinityGeneration`, and the increment itself, now require a
  safe integer. A poisoned counter is dropped rather than trusted, so the next
  `switch` writes 1 and repairs the file instead of freezing it forever.

## What's new

### `codex-multi-auth limits --json`

A stable, machine-readable quota snapshot for local integrations, so nothing has
to scrape terminal output or read the internal cache file.

```bash
codex-multi-auth limits --json
codex-multi-auth limits --json --refresh
```

The default reads the local quota cache and makes no network requests.
`--refresh` reuses the dashboard's sequential refresh and its five-minute
freshness floor, so only enabled accounts with usable credentials and a missing
or stale entry are probed.

The payload carries `schemaVersion: 1`, a millisecond `generatedAt`, a `mode` of
`cached` or `refresh`, a `selection` block, and one entry per configured account
with `index`, `label`, `enabled`, `current` and either a `quota` object or
`null`. Absent provider values are explicit JSON `null` rather than missing keys,
so a consumer never has to distinguish the two. Access tokens, internal probe
model names and orphaned cache entries are not emitted, and account emails are
masked in `label` the same way `forecast --json` masks them.

`selection` reports the configured routing target, not a live prediction:
`pinnedIndex`, the per-family `activeIndexByFamily`, and `routedIndex`, which is
the pin when one is set and the `codex` active index otherwise. Use
`why-selected --json` when you need the account the next request will actually
land on, since the proxy also skips accounts that are disabled, rate-limited,
cooling down or behind an open circuit breaker.

### `CODEX_MULTI_AUTH_RUNTIME_PROXY_UPSTREAM_BASE_URL`

Routes the runtime rotation proxy through an explicit local upstream, for
operators who chain it into a local inspection or anonymizing proxy.

```bash
CODEX_MULTI_AUTH_RUNTIME_PROXY_UPSTREAM_BASE_URL=http://127.0.0.1:8787/backend-api
```

The value must be HTTP with a numeric loopback host, either `127.0.0.0/8` or
`[::1]`, and an explicit port. A name such as `localhost` is rejected: it is
resolved by the operating system at connect time, so a hosts-file entry could
point it at a routable address, and the upstream request carries the managed
OAuth bearer token. Credentials, query strings, fragments and HTTPS are rejected
too.

It fails closed. If the value is invalid, if the proxy cannot start, or if
runtime rotation itself is disabled, a request-bearing invocation exits non-zero
rather than quietly falling back to the direct backend. Subcommands that make no
backend requests still run normally.

One thing to understand before using it: the loopback check bounds exposure to
your machine and nothing more. It does not authenticate the process listening on
that port, and a local inspection proxy needs plaintext HTTP, so any process that
can bind the port you name receives the managed bearer token in cleartext. Set
the variable only where you trust every local process that can bind a loopback
port, and only for as long as you need the chain.

## Upgrade notes

No migration is required. Nothing changes unless you run the new command or set
the new variable, and the `switch` fix needs no configuration.

```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

The command should report `2.13.0`.
