# v2.13.0

`switch` now really unblocks a rate-limited account, and there's a new `limits --json` command plus a way to chain the runtime proxy through a local upstream. Nothing to migrate.

## What's new

- `codex-multi-auth limits --json` prints a stable, machine-readable quota snapshot, so your tools don't have to scrape terminal output ([#688](https://github.com/ndycode/codex-multi-auth/pull/688)).
- By default it reads the local quota cache and makes no network requests. `codex-multi-auth limits --json --refresh` probes enabled accounts with usable credentials whose entry is missing or older than five minutes.
- The JSON has `schemaVersion: 1`, `generatedAt`, a `mode` of `cached` or `refresh`, a `selection` block and one entry per account. Missing values are `null`, emails are masked, and tokens are never included.
- `selection` shows the configured target (`pinnedIndex`, `activeIndexByFamily`, `routedIndex`), not a live prediction. Use `why-selected --json` to see where the next request will actually go.
- New `CODEX_MULTI_AUTH_RUNTIME_PROXY_UPSTREAM_BASE_URL` routes the runtime rotation proxy through a local upstream, like an inspection or anonymizing proxy ([#690](https://github.com/ndycode/codex-multi-auth/pull/690)).
- It must be HTTP with a numeric loopback host (`127.0.0.0/8` or `[::1]`) and an explicit port. `localhost`, credentials, query strings, fragments and HTTPS are all rejected.

```bash
CODEX_MULTI_AUTH_RUNTIME_PROXY_UPSTREAM_BASE_URL=http://127.0.0.1:8787/backend-api
```

## Fixes

- `switch <n>` now clears that account's rate-limit windows, so the proxy stops blocking it or returning 503 after an out-of-band quota reset. A 429 that races the switch is still kept ([#691](https://github.com/ndycode/codex-multi-auth/pull/691)).
- After a switch, the proxy drops its cached quota reading for that account and checks upstream instead of deferring on stale data.
- A failed background save (for example, Windows antivirus holding `accounts.json` open) now retries with backoff instead of throwing away rate-limit windows, cooldowns and refreshed tokens.
- A failed save during proxy shutdown is now logged and no longer breaks the shutdown.
- A corrupt `affinityGeneration` value in `accounts.json` could make running proxies miss every future switch, forever. Bad values are now ignored, and the next `switch` repairs the file.

## Heads up

- The upstream variable fails closed. If the value is invalid, the proxy can't start, or runtime rotation is off, commands that make backend requests exit non-zero instead of going direct. Other subcommands run normally.
- Security: the loopback check only keeps traffic on your machine. Any local process that can bind the port you name gets the managed OAuth bearer token in cleartext. Only set it where you trust every local process, and only while you need it.

## Upgrade

No migration needed. Nothing changes unless you use the new command or variable.

```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

It should report `2.13.0`.
