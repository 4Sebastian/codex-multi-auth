# v2.2.2

`forecast` no longer reports working accounts as unavailable.

## Fixes
- When rotation skipped an account with `token-exhausted`, that reason never cleared, so `forecast --live` kept calling a healthy account unavailable. A successful request now clears the account's skip reason.
- `forecast` now checks time-limited reasons against disk: `rate-limited` is ignored with no active reset window, and `cooling-down` is ignored when the cooldown is gone or over.
- `doctor`'s `forecast-runtime-alignment` check no longer shows a false warning for this.

## Heads up
- `circuit-open`, `token-exhausted` and `policy-blocked` are still applied as recorded, since they now clear on success.

## Upgrade
```bash
npm i -g codex-multi-auth
```
