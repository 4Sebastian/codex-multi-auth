# v2.6.1

Fixes OAuth login on WSL. Everything is behind a WSL check, so native Windows, macOS and Linux are untouched.

## Fixes

- If you had `codex-multi-auth` installed on both Windows and inside WSL, sign-in broke in both. Removing the Windows install was the only workaround ([#630](https://github.com/ndycode/codex-multi-auth/issues/630)).
- The browser now opens on WSL. It tries the Windows browser via `wslview`, then PowerShell interop, then the Linux opener, instead of a missing `xdg-open` that made login look hung.
- Manual paste now copies the URL to the Windows clipboard via `clip.exe`, not the distro's clipboard.
- The redirect is fixed at `http://localhost:1455/auth/callback`, and a Windows-side login holding that port can catch the redirect your WSL login is waiting for. `login` now explains this, shows how to find the listener on each side, and points you to `login --device-auth`, which needs no callback port.
- It only claims a port conflict when it actually sees `EADDRINUSE`. Otherwise it first suggests you probably closed the browser and should just run login again.

## What's new

- New [Windows and WSL side by side](../troubleshooting.md#windows-and-wsl-side-by-side) docs section.

## Heads up

- Windows and WSL keep separate state directories. Accounts aren't shared, so you sign in to each one separately.
- Known rough edge: a WSL login that loses the callback still waits the full five-minute poll before showing the guidance.

## Upgrade

```bash
npm i -g codex-multi-auth
```
