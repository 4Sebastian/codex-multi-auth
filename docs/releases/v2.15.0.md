# v2.15.0

Codex `image_gen` now works through the runtime rotation proxy, with the same account rotation, OAuth and usage tracking as text requests. No config migration needed.

## What's new
- The proxy now accepts `POST /images/generations` and `POST /images/edits`, plus their `/v1` aliases, and forwards them unchanged upstream ([#694](https://github.com/ndycode/codex-multi-auth/pull/694)).
- Image requests use the same auth, account selection, OAuth refresh and headers as chat requests.
- Image activity shows up in usage tracking like any other request. See [docs/reference/image-routes.md](../reference/image-routes.md).
- Image requests get at least a five-minute timeout waiting for upstream headers.
- Codex 0.154.0 now shows its built-in `image_gen` tool. Generated config adds a non-secret `x-openai-actor-authorization=codex-multi-auth-local` marker that makes Codex treat the provider as image-capable ([#695](https://github.com/ndycode/codex-multi-auth/pull/695)).
- The marker is stripped before anything goes upstream, so it never leaves your machine. `requires_openai_auth` stays `false`. See [docs/reference/imagegen-provider-compatibility.md](../reference/imagegen-provider-compatibility.md).

## Heads up
- Image requests that fail with unclear transport errors or general image errors aren't retried within one proxy request. Quota and auth rejections are handled as before.
- No model-ID substitution and no native-auth fallback. Accounts and your installed config are untouched.
- The marker is a version-sensitive shim for Codex 0.154.0 internals, not a supported API. It grants no upstream access and can't bypass auth; the local bearer is still required.
- The server-side image model revision isn't known, so this release makes no Images 2.5 claim, and exactly-once behavior across requests for image edits isn't promised.

## Upgrade
```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

The command should report `2.15.0`.
