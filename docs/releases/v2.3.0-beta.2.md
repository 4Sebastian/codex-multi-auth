# v2.3.0-beta.2

Drain-first mode from beta.0 works the same, with its pointer bug fixed plus a few other fixes.

## Fixes
- In `sequential` mode, a brief fallback to another account no longer moves you off your primary for good.
- After a token refresh, the new token is now used even if the account can't be found in storage. Before, the old token was sent, causing a `401` on a healthy account.
- Restoring a flagged account no longer loses its `workspaces`, `currentWorkspaceIndex`, `accessToken` and `expiresAt`.
- A failed disk read no longer wipes every other account's quota data.

## Heads up
- Security: temporary filenames for atomic writes now use `crypto.randomBytes` instead of `Math.random()`.
- Security: CI workflow steps are pinned to exact commit SHAs.
- Security: every response header starting with `x-codex-multi-auth-account-*` is now blocked, so new ones can't leak.
- Security: a stalled stream could time out and still be reported as success. Fixed.
- The published package no longer includes JS source maps.
- Internals: big files were split up, import cycles removed, and the config JSON schema is now generated from its Zod source.

## Upgrade
```bash
npm i -g codex-multi-auth@beta
```
