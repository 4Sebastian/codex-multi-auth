Subscription visibility and launch performance: `status`, `list`, and `check accounts` now report the selected workspace, observed plan, and first-use priming state per account, with opt-in priming for unused Pro Max subscriptions — and the shadow Codex home no longer reads multi-gigabyte linked SQLite files into memory on every launch and cleanup. (#726, #727)

## Added

- Subscription status surfaces on `status`, `status --json`, `list`, and `check accounts`: selected workspace, observed plan (`free`, `plus`, `pro`/Pro 200, `prolite`/Pro 100, `promax`/Pro 500, business/team, enterprise, edu), the account's `autoPrime` setting, first-use priming state (`awaiting-first-use`, `timer-running`, `used`, `completed`, `failed`, `not-applicable`, `unknown`), observation freshness, and any block preventing automatic priming. `status --json` exposes the same data under `accounts[].subscription`. (#726)
- `check accounts --prime` flag: opt-in first-use priming that consumes the already-opened tiny probe response (never a second request) to start an unused personal subscription's 5-hour/weekly windows. (#726)
- Automatic first-use priming for accounts whose policy sets `autoPrime: true`, now recognizing `promax`/Pro 500 alongside Plus, Pro 200, and Pro 100. Automatic checks revalidate removal, token rotation, policy, enablement, and workspace selection after every refresh I/O boundary before any billable probe. (#726)
- `byWorkspace` quota-cache namespace keyed by a hash of the credential record and workspace id, so organization members sharing an `accountId` no longer collide — and token-only accounts derive workspace identity from the access token's `chatgpt_account_id` claim. (#726)

## Fixed

- Shadow-home launches materialize SQLite databases via symlink/hardlink and stop snapshotting or syncing them back: a linked shadow file is the original file itself, so reading it only burned memory (often several GB) on every launch and cleanup. Sidecars (`-wal`/`-shm`) are covered, dangling placeholders let SQLite write fresh sidecars straight through to the original, and link identity is recorded at launch so a replaced original is never re-read at cleanup. (#727)
- Forked rollouts index and display by their first `session_meta` record — a forked rollout appends the parent's metadata after its own, which previously hijacked the rollout id and listing title. (#727)
- Concurrent quota-cache writers no longer lose priming outcomes: `primingObservedAt` merges priming evidence independently of the quota timestamp, an overlapping timeout can't erase a completed first-use, and a genuinely newer observation still retires stale evidence. (#726)
- Strict account-policy reads reject malformed `autoPrime`/`paused`/`drained` values and surface store load failures as `unknown` in status output instead of falsely reporting priming as off. (#726)
- Disabled or invalid workspace selections never silently fall back to a sibling workspace or the stored binding — including token-only accounts, which previously could surface the legacy email-keyed binding entry. (#726)

## Security

- `undici` 6.28.0 → 6.29.0: fixes high-severity advisories for WebSocket permessage-deflate decompression DoS, response splitting via the retry interceptor, and unrequested WebSocket subprotocol DoS.
