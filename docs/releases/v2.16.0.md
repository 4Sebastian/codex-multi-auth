# v2.16.0

Adds GPT-6 Sol and GPT-6 Luna, and every retired model now runs on its named replacement. Retired model ids in your config keep working, and accounts and pools are unchanged.

Landed as [#696](https://github.com/ndycode/codex-multi-auth/pull/696), [#697](https://github.com/ndycode/codex-multi-auth/pull/697) and [#698](https://github.com/ndycode/codex-multi-auth/pull/698).

## What's new

- `gpt-6-sol` and `gpt-6-luna` are supported. Sol runs `low` to `ultra`, Luna runs `low` to `max`, and both default to `medium`.
- Both are priced at the published rates, Fast mode included, and are listed in both config templates.
- `gpt-6-terra` resolves to Sol. Bare `sol` and `luna` still mean the GPT-5.6 tiers.

## Fixes

- In 2.15.0, `gpt-6-sol` and `gpt-6-luna` actually ran GPT-6 Astra, so a Luna request cost $10 / $50 per 1M tokens instead of $0.10 / $0.50. Fixed.
- Retired models (everything older than GPT-5.5) are no longer sent under names the backend doesn't serve. They now run as:

| Retired | Now runs as |
| --- | --- |
| any codex id (`gpt-5.3-codex`, `gpt-5-codex`, `codex-max`, ...) | `gpt-5.6-sol` |
| codex minis (`codex-mini-latest`, `gpt-5.1-codex-mini`, ...) | `gpt-5.6-terra` |
| `gpt-5.4` | `gpt-6-sol` |
| `gpt-5.4-mini`, `gpt-5.4-nano` | `gpt-6-luna` |
| `gpt-5.4-pro`, `gpt-5.2-pro` | `gpt-5.5-pro` |
| `gpt-5.2`, `gpt-5.1`, all `*-chat-latest` | `gpt-5.6-sol` |
| `gpt-5-mini` / `gpt-5-nano` | `gpt-5.6-terra` / `gpt-5.6-luna` |

- Effort-suffixed and provider-prefixed ids map the same way. If a retired id still reaches the backend through the pass-through proxy, it retries once on its replacement.
- Usage under a retired id is priced at the replacement's rate. Cost already in the ledger is not re-priced.
- The fallback chain now ends at `gpt-5.5` / `gpt-5.5-pro`, and the quota probe tries `gpt-5.6-sol`, `gpt-5.5`, `gpt-6-luna` instead of dead models.
- GPT-6 requests over 272,000 input tokens now use the long-context rates (standard and Fast), so a `maxCostUsd` budget no longer overruns on big sessions.
- `status -m <codex model>` now reads the same account slot the proxy actually uses.

## Heads up

- Codex ids now use the `gpt-5.2` prompt family and rotation bucket. Per-family account assignments saved under `gpt-5-codex`, `codex-max` or `gpt-5.1` are no longer used.
- A direct `gpt-5.6-luna` or `gpt-5.6-terra` request that gets an unsupported-model response now retries on `gpt-5.5` instead of stopping. The wrapper always retries. The plugin host only retries when `fallbackOnUnsupportedCodexModel` is on.
- `fallbackToGpt52OnUnsupportedGpt53` is still accepted in config but does nothing.
- The context budget guard no longer estimates a window for codex ids, since they now run on `gpt-5.6-sol`, which it deliberately doesn't estimate.

## Upgrade

No migration needed. Existing accounts, pools and config are unchanged.

```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

It should report `2.16.0`.
