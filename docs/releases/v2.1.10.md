# v2.1.10

A long-running proxy no longer stays stuck after your accounts have recovered.

## Fixes
- When the pool ran out of usable accounts, a running proxy could keep refusing requests even after the accounts on disk had recovered. It now reloads accounts from disk once and tries again.
- Pool-exhausted `503`s now tell you why each account was skipped, with a hint on how to recover.
- `report` and `doctor` count cached quota state, so an account with exhausted quota is no longer reported as ready.
- `rotation reset-runtime --json` no longer wipes diagnostics when the app-bind restart fails.
- The npm package now ships only runtime and install scripts, dropping internal benchmark, audit and maintenance ones.

## Heads up
- Pinned accounts are unaffected: an unavailable pinned account still fails outright instead of quietly switching to another one.

## Upgrade
```bash
npm i -g codex-multi-auth
```
