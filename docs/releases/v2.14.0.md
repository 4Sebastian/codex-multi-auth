# v2.14.0

Long tasks no longer die when the backend says the model is at capacity. The runtime proxy now waits and re-sends instead of burning through your accounts. No config migration needed.

## What's new
- When a response says the model is at capacity, the proxy waits and retries instead of rotating through every account (which all fail the same way) and ending in a 503. ([#692](https://github.com/ndycode/codex-multi-auth/pull/692), closes [#689](https://github.com/ndycode/codex-multi-auth/issues/689))
- Waits back off 2s, 5s, 15s, 30s, then 60s. An upstream `retry-after` header or body value wins if sent.
- It gives up at a wall-clock deadline set by `CODEX_MULTI_AUTH_MODEL_CAPACITY_RETRY_MS`: 10 minutes by default, 1 hour max. The deadline covers the whole request, not just time spent waiting.
- The account that got the capacity response is not penalized. It is never marked rate limited or cooled down.
- If the client disconnects during a wait, the request is dropped. No more upstream calls for nobody.

## Heads up
- Set `CODEX_MULTI_AUTH_MODEL_CAPACITY_RETRY_MS` to `0` to get the old rotate-and-fail behaviour. A value that can't be parsed falls back to the default, so a typo won't turn it off.
- Rate limits, entitlement failures and real server errors work as before. `401`, `402`, `403` and `404` never take the new path.
- Known limitation: the capacity response format isn't documented, so detection matches message text. Recognized: `at capacity`, `model_capacity_exceeded`, `capacity_exceeded`, `currently overloaded`, `overloaded_error`, `slow_down`.
- If your capacity error uses other wording, nothing changes and behaviour is the same as 2.13.0. Please open an issue with the raw body so the pattern can be widened.

## Upgrade
Nothing changes unless a capacity response arrives.

```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

The command should report `2.14.0`.
