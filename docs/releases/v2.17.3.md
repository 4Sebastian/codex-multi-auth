Maintenance release landing an eighteen-PR review-and-hardening stack: every merged change went through adversarial re-review, and the fixes below include both the externally flagged findings and additional defects surfaced by stress testing the stack as a whole.

## Changed

- Account dedup keeps incremental identity indexes instead of rescanning the pool on every operation. (#708)
- Runtime policy stores are cached per request with mtime+ctime+size fingerprinting, post-load stability rechecks, and ancestor-directory tracking; one ledger summary is shared per evaluation. (#709)
- Request transformation allocates less on the hot path: a fused clone path inspects property descriptors without invoking getters and falls back to the legacy path for accessors, proxies, and `required: []` schemas; circuit-breaker probes no longer throw. (#716)
- Backup rotation is throttled and keys on credential signature (account count plus refresh-token set) instead of count alone. (#712)
- The npm tarball is smaller, typecheck is faster, forward-path imports are slimmer, `skills/` now ships in the package, and the `brace-expansion` security pin is a live self-reference override instead of dead configuration. (#711, #722)
- Property suites now cover storage, transformer, SSE, budget, and redaction round-trips under a sorted-multiset oracle; chaos suites add real filesystem/network fault injection and live concurrency coverage with a harness that drains IPC on close and survives post-death sends. (#714, #715)
- Living documentation rewritten from the audited architecture; the v2.17.1 notes (prepared but never published) are restored as their own entry. (#718, #707)

## Fixed

- OAuth log redaction covers bearer-first ordering, URL fragments, nested query values, encoded and double-encoded separators, token-like hostnames, credential suffixes, and secrets smuggled as JSON key names; chunked entropy scrubbing avoids regex overflow on multi-megabyte payloads. (#719)
- Audit logs and rotated backups are re-asserted `0600`, malformed local-client token digests are rejected, non-email `@` identifiers are no longer mangled, Windows root-relative binary overrides are refused on both root forms, and `AbortSignal.any` replaces a listener-leaking signal combiner. (#710)
- Overlong email labels can no longer defeat partial masking — the pattern is boundary-anchored and linear on multi-megabyte inputs — and timeout values above the 32-bit timer ceiling no longer clamp to near-zero instant failover. (#721)
- Cross-process governance stores (account policy, budget, routing profiles) mutate under the proven directory lock with compare-and-swap retry; dead-owner cleanup can never evict a live holder. (#713)
- Clock skew can no longer lose writes: raced quota observations keep the higher stamp and baseline-aware config merges land deliberate edits on the freshest record while baseline-less saves keep last-writer-wins compatibility. (#723)
- Backup rotation keeps a `.bak` holding a still-spendable refresh token, chained rotations keep intermediate pending-auth entries so a restored backup self-heals, and foreign writes are detected by content fingerprint. (#712)
- V1→V3 migration preserves V3-era and unknown fields, existing `rateLimitResetTimes` maps, and `activeIndexByFamily`; the strict schema no longer strips hybrid rows before migration. (#717)
- Budget and routing-profile merges treat `constructor` and `__proto__` as plain keys via null-prototype maps. (#714)
- The wrapper relays repeated signals until the forwarded child closes, sweeps only dead-owner shadow homes verified by PID start time, and finalizes force-kill timers after close. (#720)
- Active-account sync fingerprints canonical storage plus every official mirror file, so a forwarded `codex login`/`logout` cannot leave the mirror stale while reporting clean. (#711)
- Reset-credit checks discover the relocated ChatGPT desktop backend (`codex-cli/bin/codex` layout before the legacy one), require executable bundled candidates, exit 1 on partial refresh failures, and reject ambiguous duplicate account identities before any read or redemption. (#724, thanks @bayan9)
