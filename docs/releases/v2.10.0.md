# v2.10.0

A pinned account now retries a failed request instead of giving up after one try, and a new opt-in guard can pause a session before it overflows the model's context window. Nothing to migrate.

## What's new
- **Context Budget Guard (experimental, off by default).** Turn it on in Settings → Experimental, or set `contextBudgetGuardEnabled` in `settings.json`.
- It tracks how full each session's context window is and, past the hard threshold, answers the next request locally with a notice suggesting `/compact` or `/clear`, instead of waiting for a `context_length_exceeded` 400.
- Soft threshold (default 65%): adds an `x-codex-context-budget-percent` response header. Set it with `contextBudgetGuardSoftPercent`.
- Hard threshold (default 69%, floor 10): pauses the next request locally. Set it with `contextBudgetGuardHardPercent`.
- Model window overrides: set a model's real observed ceiling with `contextBudgetGuardModelWindowOverrides`. It always beats the built-in estimate.
- It works on both the plugin-loader fetch path and the rotation proxy. It does nothing for a client that sends no session, conversation, `prompt_cache_key` or `metadata` id, and records nothing while disabled.
- See [Context Budget Guard](../features.md#context-budget-guard-experimental) and the [settings reference](../reference/settings.md#experimental).

## Fixes
- A pinned account (`codex-multi-auth switch <n>` or `--account`) used to get exactly one upstream attempt, then a `codex_pinned_account_unavailable` 503. It now gets up to four attempts, spaced 250ms, 500ms and 1s apart.
- The retry budget is `min(retryAllAccountsMaxRetries + 1, 4)`, with a 16-pass ceiling.
- The retry only skips the pin's own cooldown. Rate limits, an open circuit breaker, a disabled account (or no enabled workspace) and policy blocks (pause, drain, budget) still stop it.
- A pin that was already cooling down when the request arrived is still refused without an upstream call. The cooldown still applies to other requests and still sets the 503's `retry_after_ms`.
- A busy pinned session no longer gets a `token-exhausted` 503 while the account is healthy. Pinned requests skip the pool token bucket. Circuit-breaker checks still apply.
- `account_skip_reasons` (shown by `codex-multi-auth rotation status`) now names the check that actually refused the account, `token-exhausted` or `circuit-open`, instead of guessing from account state.

## Heads up
- The context window sizes are estimates, not published facts. Per [the v2.5.0 notes](v2.5.0.md), the window OpenAI's API docs advertise may not match what the ChatGPT Codex backend serves. Set `contextBudgetGuardModelWindowOverrides` once you know a model's real ceiling. Models with no estimate are skipped.
- The pause fires once per measurement. The next request is forwarded and re-measured, so a session that really compacted stays quiet and one that didn't is paused again on the following turn.
- Nothing changes for an unpinned pool. A `2.9.2` install that turns nothing on behaves the same, except pinned requests now retry transient failures.

## Upgrade
```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

The command should report `2.10.0`.
